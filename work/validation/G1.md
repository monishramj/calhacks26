### Test-design choices for review

- **Empty and whitespace-only text is rejected at the sender.** §20 allows "exact or explicit rejection". A report with no content carries nothing for the incident desk.
- **Rejection reasons name the field** (`method`, `type`, `utf`). That is a requirement on `parse_packet`'s existing `reason` string, not a new contract field.
- A forced method may refuse text it can't carry. Auto selection may not, because raw always works up to the size limit.

### Not covered here (belongs to G2 or later)

- The direct-message size ceiling and message-ID/version framing: G2 (preflight probe in `work/status/codec-radio.md`).
- Cross-machine decode on the actual two endpoints: G1 REVIEW.
- Windows runtime: the Windows build and a compiler-free Unishox2 come in G1 IMPLEMENT/REVIEW. `unishox2-py3` has no Windows wheels.

## IMPLEMENT · 2026-10-25 01:45 PDT · Claude (C1 agent), supervised by Sud

- **Files changed:**
  - `codec/mesh_codec.py`: boundary code only. The `Encoder`/`Decoder`, `freq_table`, `WTABLE` and model calls are untouched.
    - `build_packet` no longer normalizes. It rejects empty/blank text and validates type, priority (0..3), people (0..255), location (two ints 0..65535), model id and forced method with `ValueError`. It picks the smallest method that reproduces the text exactly; Unishox2 is verified by round trip before use.
    - `SharedModel.compress`/`explain` return None for text containing a newline (the coder's terminator), so that text goes raw or Unishox2.
    - `parse_packet` never raises. It checks length, method, type, optional-field lengths, an empty body, strict UTF-8 in raw bodies and bounded Unishox2, then the CRC. Reasons are named.
  - `codec/unishox2.py`: new. Bounded Unishox2 via ctypes, same C source as `unishox2-py3` 1.0.0; compression byte-identical on 404/404 strings. `third_party/unishox2/` holds the source and `usx_bounded.c`. Built into `runtime/{win-x64,linux-x64}/`; macOS builds it on first use.
  - `codec/poc_run.py`: encodes and records the original text; explicit rejections are recorded, not hidden.
  - `codec/runtime.py`: new loader on the pinned runtime (D-005), with hash checks for runtime/model/context, `fingerprint()` and the reference `422ac23fca10`.
  - `runtime/win-x64` and `runtime/linux-x64`: pinned llama.cpp binaries plus Unishox2, with `SHA256SUMS`. `third_party/llama_cpp` (bindings 0.3.36, pure Python), `third_party/detmath` (glibc 2.39 float math for the Windows build), `tools/runtime-build/` (recipe, `build_runtime.sh`, logits harness, `detmath_check.c`).
- **Test harness only (no assertion changed):** `conftest.py`'s `model` fixture and `test_g1_callers.py` now load the pinned runtime from `runtime/<platform>/`, so endpoints need only `CODEC_MODEL_PATH`.
- **Command:** `CODEC_MODEL_PATH=<gguf> python -m pytest services/codec-radio/tests -q -rs` with no `PYTHONPATH`, no `LLAMA_CPP_LIB_PATH` and no pip `unishox2-py3` installed.
- **Green result:** **104 passed, 0 skipped**, real model, on Linux x86-64 (Intel Xeon container), pinned `runtime/linux-x64`.
