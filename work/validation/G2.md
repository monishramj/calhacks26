# G2 validation · ws/codec-radio

Ship mode (D-009): one request. The bridge is implemented, has run in-process, and is **waiting for the real two-radio run**.

## IMPLEMENT · 2026-10-25 02:55 PDT · Claude (C1 agent)

- **Contract:** G0 v1 on `main` (`packages/domain`), radio-intake transport as frozen in `packages/domain/README.md`. Every `ReportInput` is checked with `domain_contract.validate` before it is sent.
- **Code:** `services/codec-radio/bridge/` (`envelope.py`, `radio.py`, `core.py`, `intake.py`) and the CLI `tools/radio_bridge.py` (`identity`, `rx`, `send`).
- **Envelope:** REPORT = 10 B header (version|kind, u32 message ID, attempt, u32 sender time) + codec packet. DECODE_ACK = 7 B, sent without want_ack and never answered.
- **Behavior:**
  - Direct message on PRIVATE_APP (256) with want_ack.
  - The message ID is stable across the raw retry. At most one raw retry, on DECODE_FAILED or a missing decode ACK.
  - Oversized or empty text is rejected before sending. No truncation, no fragmentation.
  - Radio ACK, decode ACK and human reading are reported separately.
  - Duplicates get a fresh decode ACK but no second intake. Same ID with different text goes to the backend as a visible conflict.
  - The receiver persists each report before intake (`state/delivered-<run>.jsonl`), so a restart never re-ingests it. Failed intakes stay pending and are retried.
  - Every frame and ACK byte is logged.
- **Codec boundary fix found while building:** `SharedModel.compress` encoded any length, but `decompress` stops at 300 tokens. Long reports became undecodable on the receiver. `compress` now refuses more than `MAX_LLM_TOKENS` (300), so such text goes Unishox2/raw or is rejected as oversized. Encodings under the bound are unchanged: the 8/8 probes are byte-identical and the fingerprint is still `422ac23fca10`.
- **Second fix:** the bridge serializes model use with a lock. Concurrent encode and decode on one llama context segfaulted in the in-process run.
- **Ran (simulated radio, real model, Linux pinned runtime):** an in-process fake radio pair, not a committed suite (D-009).
  - Passed: basic LLM send (69 B text → 29 B frame, 36 B on air including the ACK); exact whitespace/Unicode; duplicate → one intake; conflict; corrupted attempt 1 → raw retry → verified; all frames dropped → NOT_DELIVERED after 2 attempts; decode ACKs lost → RADIO_ACK_ONLY with one intake; late decode ACK; oversized and empty rejected unsent; exactly one ACK per report (no loop); garbage frames ignored; restart dedupe; LLM refused past 300 tokens.
  - The intake HTTP request was checked against a local server: correct path, `Bearer` header, body `["<ReportInput JSON>"]`, Unicode exact.
- **Not run here:** the existing G1 pytest suite. pytest is unavailable in this container (PyPI blocked). The only codec change returns None above 300 tokens, and no existing test uses text that long. **Run it on C1 or C4** (requirements.txt now includes pytest).
- **Unavailable until the hardware run:** real RF delivery, real timings, the measured payload ceiling, SpacetimeDB acceptance with the `bridge` role (G3, ws/state).
